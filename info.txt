==============================================================================
 ShymaBot — что умеет бот (обзор возможностей)
 Обновлено: 2026-07-20
==============================================================================

Телеграм-бот — личный помощник: заметки, напоминания, календарь, калькулятор
оценок. Мультиязычный, с уровнями доступа и админ-панелью. Работает на вебхуках
(Render) с внешней базой Neon Postgres и горячим резервом.

Навигация — через инлайн-меню (кнопки). Открывается по /start.


------------------------------------------------------------------------------
 1. КОМАНДЫ
------------------------------------------------------------------------------

/start    — приветствие + главное меню (регистрирует пользователя).
/stop     — помечает пользователя неактивным, чистит его временные данные и лог.
/support  — контакт/справка поддержки.
/whoami   — показывает твой Telegram ID и уровень доступа (admin / prime / common).
/prime    — отправить заявку на prime-доступ (то же, что кнопка в меню).
/cancel   — отменить текущий пошаговый ввод (напоминание, заметка, календарь…).


------------------------------------------------------------------------------
 2. УРОВНИ ДОСТУПА
------------------------------------------------------------------------------

Три уровня: common (обычный) < prime (привилегированный) < admin (владелец).

- admin  — определяется по ADMIN_ID в переменных окружения (не по нику: id
           неизменен и не перехватывается). Видит админ-панель и все модули.
- prime  — доступ к модулям, помеченным «только prime». Членство хранится в БД,
           переживает рестарт и попадает в резервную базу.
- common — обычный доступ. В меню видит кнопку «⭐ Запросить доступ».

Как стать prime:
- пользователь жмёт «⭐ Запросить доступ» (или /prime) → заявка падает в очередь
  админ-панели (с id, username и временем), админу приходит уведомление в личку;
- админ одобряет/отклоняет заявку (при одобрении юзеру приходит уведомление);
- либо админ добавляет prime вручную по числовому ID.


------------------------------------------------------------------------------
 3. МОДУЛИ (пункты главного меню)
------------------------------------------------------------------------------

3.1. 🗄 ШКАФ ПАМЯТИ (заметки)
- Полки: создать / удалить (с подтверждением). Заметки изолированы по владельцу.
- Заметки внутри полки: создать / редактировать / удалить.
- Ограничения: название полки ≤ 255 символов, текст заметки ≤ 4000.

3.2. ⏰ НАПОМИНАНИЯ
- Быстрый выбор «когда» — папками:
    • ⏱ Через N часов: 🕐 «в котором часу» (00–23, сегодня или завтра, если
      час уже прошёл) ИЛИ ⏱ «через N часов» (1–24);
    • 📅 Через N дней: сетка 1–30 + неделя / месяц / полгода / год; по
      умолчанию «то же время, что сейчас» (сразу текст), опция «другое время»
      → выбор часа → минуты (как в «часах»).
- Точный ввод — пошагово, ничего не проскакивает (пользователь сам выбирает):
    • Шаг 1 «Дата»: кнопки «Сегодня» / «Завтра» / «Другая дата» или ввод
      ДД.ММ.ГГГГ вручную;
    • Шаг 2 «Время»: кнопки-пресеты часа (09:00…21:00) или ввод ЧЧ:ММ вручную;
      при тапе на пресет часа бот спрашивает «Ровно HH:00 или выбрать минуты»,
      минуты — сетка 00, 05, … 55; есть «⬅️ Назад к дате».
    • Для ежедневного — только шаг времени (даты нет).
    • Для интервала — шаг «длительность» (пресеты 10m…1d или ввод), затем
      момент старта: «прямо сейчас» или указать дату→время.
- Типы повтора: разовое, ежедневно, еженедельно, ежемесячно, интервал.
- Прошедшая дата/время для разового не принимается — бот вернёт на шаг даты.
- Когда напоминание приходит — кнопки отложить (snooze): «+10 мин», «+1 час»,
  «Завтра 09:00».
- Правка существующего: изменить текст; изменить время/тип (переключатель
  формата доступен и здесь).
- Валидация ввода с понятными ошибками (время в прошлом, неверный формат,
  границы интервала). Время — в местном поясе (по умолчанию Europe/Berlin),
  хранится в UTC.
- Доставка не зависит от «сна» сервера: срабатывания рассылает внешний cron
  через эндпоинт /tick (см. раздел 5).

3.3. 📅 КАЛЕНДАРЬ (подписка на ICS)
- Подключить календарь по ссылке ICS (Google/Apple/Outlook «экспорт/публичный
  адрес»). Один фид на пользователя.
- Обновить сейчас (ручной синк) + автоматический синк по /tick.
- Напоминание перед событием: настраиваемое «за сколько» (пресеты + своё число
  минут).
- Сменить ссылку / отключить календарь (с подтверждением).
- Надёжность: скачивание с таймаутом и повторами (backoff), битый ICS не роняет
  синк; текст последней ошибки виден на экране модуля.
- Приватность: ссылка не пишется в логи и не показывается целиком — только домен.

3.4. 🎓 ОЦЕНКИ (Notenrechner)
- Предметы: создать / переименовать / удалить (с подтверждением).
- Две шкалы на выбор при создании предмета:
    • points (баллы 0–15, FOS/Oberstufe, больше = лучше);
    • marks  (оценки 1–6, обычная школа, меньше = лучше).
- Типы оценок: SA (Schulaufgabe), KA, Mündlich/Ex. В шкале 1–6 — только SA и
  Mündlich.
- Средний по предмету по «правильной» формуле каждой шкалы:
    • баллы 0–15: маленькие = (2·ΣKA + ΣMündl)/(2·nKA+nMündl);
      итог = (SA-средняя + маленькие-средняя)/2;
    • оценки 1–6: взвешенное среднее, каждая SA с весом 2, остальное с весом 1.
- Общий средний (Gesamtschnitt) — отдельно по каждой шкале.
- Добавить / удалить отдельные оценки; валидация значений по границам шкалы;
  лимиты на число предметов/оценок.

3.5. 🌐 ЯЗЫК
- Переключение языка интерфейса: русский, English, Deutsch, українська
  (украинский — в шутливом стиле). Язык сохраняется и используется в том числе
  фоновыми уведомлениями (/tick).

3.6. ⚙️ АДМИН-ПАНЕЛЬ (только admin)
- 🔌 Модули: у каждого модуля вкл/выкл (техобслуживание) + уровень доступа
  «👥 всем / ⭐ только prime». Выключенный модуль виден с пометкой 🔧, обычный
  юзер получает сообщение «идут технические работы».
- ⭐ Prime-доступ: список участников (снять), очередь заявок (одобрить/отклонить),
  добавить prime по числовому ID.
- 🗄 Базы данных: статус каждой базы — активна / резерв / недоступна + занятый
  объём и число пользователей (только просмотр; активную выбирает сам бот).
- 📜 Ошибки: журнал последних ошибок (до 20), с очисткой.


------------------------------------------------------------------------------
 4. ЯЗЫКИ
------------------------------------------------------------------------------

Полностью переведён интерфейс (меню, все модули, кнопки, тексты ошибок,
фоновые уведомления): ru / en / de / uk. Язык определяется автоматически по
языку Telegram при первом входе, дальше — по выбору пользователя.


------------------------------------------------------------------------------
 5. КАК УСТРОЕНО ВНУТРИ (инфраструктура)
------------------------------------------------------------------------------

- Стек: python-telegram-bot 22.3 + FastAPI (вебхук), хостинг Render (free),
  база данных Neon Postgres (SQLAlchemy async + asyncpg).
- Вебхук: Telegram присылает апдейты на сервер; постоянный поллинг не нужен.
- Внешний cron дёргает /tick (раз в ~10 минут, защищён секретом X-Tick-Key).
  За один /tick происходит:
    • рассылка созревших напоминаний (+ пересчёт следующего срабатывания);
    • синхронизация ICS-календарей и напоминания о ближайших событиях;
    • обновление «метки свежести» активной базы;
    • раз в сутки — зеркалирование активной базы в резерв.
- Экономия ресурсов Neon: NullPool (соединение закрывается сразу после запроса),
  чтобы compute-часы не выгорали от простаивающих соединений.

Горячий резерв базы данных:
- Две базы: DATABASE_URL (основная) и DATABASE_URL_2 (резерв), одинаковая схема.
- При старте бот сам выбирает активную: из достижимых — с самыми свежими данными,
  при равенстве предпочитает основную. Это даёт авто-переключение на резерв, если
  основная недоступна, и авто-возврат после выравнивания данных.
- Раз в сутки активная база целиком копируется в резерв (потеря при аварии —
  максимум за сутки).

Обработка ошибок:
- Полный traceback уходит в лог сервера.
- Обычный пользователь видит нейтральное «идут технические работы» — внутренние
  детали не утекают.
- Админ получает настоящий текст ошибки в личку (с антифлудом — не чаще раза в
  минуту на один тип) и видит журнал в админ-панели.
- Недоступность базы не роняет старт сервиса: бот поднимается, функции с БД
  деградируют мягко.


------------------------------------------------------------------------------
 6. ДАННЫЕ (таблицы в БД)
------------------------------------------------------------------------------

users            — пользователи (telegram_user_id, username, язык).
shelves / notes  — полки и заметки «шкафа памяти».
reminders        — напоминания (текст, next_fire_at, тип повтора, интервал).
calendar_feeds   — подписка на ICS (URL, «за сколько минут», статус синка).
calendar_events  — события из фида в ближайшем окне (для напоминаний).
grade_subjects   — предметы (название, шкала points/marks).
grade_entries    — оценки (тип SA/KA/Mündlich, значение).
prime_users      — привилегированные пользователи.
prime_requests   — очередь заявок на prime.
app_settings     — глобальные настройки (флаги модулей, уровни, метки БД).


------------------------------------------------------------------------------
 7. ПЕРЕМЕННЫЕ ОКРУЖЕНИЯ (.env / Render)
------------------------------------------------------------------------------

BOT_TOKEN       — токен Telegram-бота (обязательно).
WEBHOOK_URL     — базовый адрес сервиса для вебхука (обязательно).
DATABASE_URL    — строка подключения к основной базе Neon.
DATABASE_URL_2  — строка подключения к резервной базе (горячий резерв).
ADMIN_ID        — числовой Telegram ID администратора (узнать через /whoami).
TICK_SECRET     — секрет для эндпоинта /tick (внешний cron).
REMINDER_TZ     — часовой пояс для напоминаний (по умолчанию Europe/Berlin).
