## 2. Детали

### [01] Напоминания через внешний cron + /tick — Prio: 5 — Datum: 2026-06-23
- Beschreibung: free web service Render засыпает через 15 мин -> in-process планировщик во сне не сработает.
- Wie umsetzen: хранить `next_fire_at` в БД (Neon); внешний бесплатный cron (cron-job.org / GitHub Actions)
  дёргает эндпоинт `/tick` раз в N минут; эндпоинт выбирает «созревшие» напоминания и отправляет их.
- Was wird geändert: `bot/features/reminders/tick.py`, маршрут webhook-сервера, схема БД.
- Status: erledigt (Шаг 4) — `features/reminders/tick.py` + POST `/tick` (секрет X-Tick-Key) +
  поле `next_fire_at` в таблице `reminders`; внешний cron-job.org раз в 5 мин.

### [09] Больше способов ввода даты/времени — Prio: 4 — Datum: 2026-07-01
- Beschreibung: сейчас только строгий формат (ДД.ММ.ГГГГ ЧЧ:ММ / ЧЧ:ММ / 30m). Дать несколько
  путей ввода параллельно.
- Wie umsetzen:
  - **Пресеты-кнопки**: «Сегодня вечером», «Завтра утром», «Через 1 час», «На выходных» —
    самый дешёвый и мощный шаг (1 тап покрывает ~80% случаев). Низкий риск, высокий эффект.
  - **Естественный язык**: «завтра в 15», «через 2 часа», «в след. понедельник» — нужна
    библиотека (напр. `dateparser`, поддержка ru/de) = новая зависимость.
  - **Относительное время**: «через 30 мин / 3 дня» (уже частично есть как interval для повторов —
    добавить как разовое).
  - **Только дата (ganztägig)** и **без даты (Someday)** — новые типы, требуют поля в модели.
- Was wird geändert: `features/reminders/schedule.py` (+парсеры), `handlers.py` (+кнопки/шаги).
- Status: offen. Рекомендую начать с **пресетов** (без новых зависимостей).
